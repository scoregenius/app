01  What this isScoreGenius

One vocabulary, four screens

A design system is not a style guide. It is the set of decisions already made, so that building a screen is assembly rather than invention — and so two people building two screens produce one product.

What it governs

Everything inside the application: the four screens users spend time in — Games, Stats, How to Use and More — and the components they are built from. The marketing site and the brand layer — icon, splash, wordmark — are governed separately and are not changed by it.

How to use it

Building a screen: assemble from the component library; if something is missing, add it there rather than styling locally. Changing one: check the defect register first. Settling an argument: the principles decide most, and the tiebreaker is whichever option better serves someone scanning fifteen items at arm's length.

The one rule that is not negotiable

Every change ships in both themes. A token defined in only one theme is a defect, not an omission — three such defects were found in the pre-existing interface, one of which made a card's background go transparent on hover in light mode.

Where it lives

The full specification is maintained in the repository alongside the code, so it travels with the product rather than living in a design tool. This document is its summary.

02  PrinciplesScoreGenius

Six rules

These are ordered. When two conflict, the earlier one wins.

#PrincipleWhat it decides in practice
1The model's output is the loudest thing on screenPredicted scores outrank team names, which outrank market data. If a change makes the prediction quieter, it is wrong.
2Rarity earns emphasisA high edge appears on two cards in fifteen, so it gets colour, a rail and a glow. Team names appear on all fifteen, so they get none. Corollary: an indicator that appears on every item and always says the same thing should not exist at all.
3Absence is silentMissing data shortens the layout; it never prints a placeholder. Fifteen rows of "N/A" reads as broken software.
4Numbers are monospace, words are notEvery figure is tabular so columns align down a long list. This single rule does most of the work of making the product read as instrumentation.
5Never imply precision the data lacksIf the app cannot measure it, the app does not display it. No confidence figures, no live detail the feed does not carry.
6Both themes ship togetherA colour defined in one theme only is a defect.

Why the neutrals look like that

They carry a slight blue-green bias rather than being pure grey, so they sit with the brand mark rather than beside it. A pure mid-grey reads as unconsidered. Colour is signal, never decoration

There is no red / amber / green status ramp

Nothing in this product is an error a user can act on. A failed request is treated as absent data, or falls back to the offline state. Introducing a semantic colour ramp would dilute green, which currently means one thing only.

Two faces, two jobs

The separation is functional, not stylistic. Anything that is a number, or labels a number, is monospaced. Everything else is proportional.

JetBrains Mono — scores, odds, times, percentages and every uppercase micro-label. Tabular figures by default. Fallback: IBM Plex Mono, then the system monospace stack, which is available everywhere at no download cost.
The sans face is specified, not yet shipped

No font file is served today, so the interface resolves to the system UI sans and the monospace stack resolves to Consolas. The monospace rule above is unaffected and does ship, because it holds on the fallback stack — which is the half of this page that does the work. Adopting Archivo means self-hosting the files; it is recorded as an open decision, not an oversight. A previous build fetched a third face from a font CDN that no rule referenced; that request was removed rather than replaced.

A serif is configured and deliberately unused

PT Serif remains in the framework configuration for the marketing pages. It has no job in a scoreboard, and does not appear anywhere in the application interior.

A defect this replaces

The pre-existing header used pure black beneath an app ground of #0d1117, producing a visible seam across the top of every screen. Using the ground token removes it.

Icons

A single open-source icon set, 1.8px stroke, sized 13px in chips, 16px in controls and 20px in the bottom bar. Icons support a label; they rarely replace one. The exceptions are the chevron and the bottom bar, where the label sits directly beneath.

No emoji in the interface

Emoji render differently on every platform, ignore the theme, and cannot inherit colour. The pre-existing interface used them for the indoor-venue and no-prediction markers; both become proper glyphs that follow the current text colour.

Why no error state

The application has no user-actionable errors. A failed request means a value is missing, and principle 3 already says what to do about that: shorten the layout and say nothing. An error dialogue would ask the user to solve a problem they cannot solve.

07  PatternsScoreGenius

How components combine

Scanning a long list

The recipe that makes fifteen cards readable at a glance. It generalises to any list in the product.

1A fixed anchor columnAn abbreviation chip starts each row, so the eye locks on without parsing a long name.
2A fixed value columnRight-aligned and tabular, so values align down the list regardless of digit count.
3Contrast marks importanceThe item of interest keeps full contrast; the rest recede. No extra chrome.
4Rare signals get one loud treatmentColour, border and rail together — not several quiet hints.

Absence and fallback

SituationResponse
A value in a group is missingOmit it; the group closes up
Every value in a group is missingOne muted line, or omit the group
An optional section is emptyOmit the section
A paired value has only one halfOmit both — half a moneyline is meaningless
Data is genuinely pendingSay so once, plainly
Never "N/A". Never an em-dash placeholder. Never an empty row where a value would be.

State encoded in form

LiveOrange, pulsing dot, rail
Finished68% opacity, score held
Model's pickFull contrast + triangle
High edgeRail, border, wash, glow
Each survives a squint, and none depends on colour alone.

Progressive disclosure

Collapsed carries what you need to decide whether to look closer; expanded carries the rest. The chevron indicates state and rotates on open. On desktop, where there is room, cards open by default.

Per-sport variation is additive

The card is one component across baseball, American football and basketball. The differences are three: probable pitchers appear for baseball only, the weather chip is dome-aware for football and absent for basketball, and the value column is sized for the widest case across all three so its edge never moves.

09  AccessibilityScoreGenius

WCAG 2.1 AA

Treated as a build requirement rather than an audit item. Several of these rules shaped the palette and the state encoding directly.

RequirementRule
Text contrast4.5:1 for body; 3:1 for 18px+ or 14px bold. This is why the green text token exists.
Non-text contrast3:1 for control borders, focus rings and the edge chip's border
Touch targets44 × 44px minimum, reached with padding where the visible element is smaller
FocusEvery interactive element has a visible focus state: a 2px green ring at 2px offset. Suppressing the outline without a replacement is a defect
MotionAll animation respects the reduced-motion preference; meaning never depends on movement
Colour independenceNo meaning is carried by colour alone — the edge tier also varies by border, glow and label; the pick also has a triangle; live also has a word
SemanticsCards are articles; expandable regions carry expanded state; toggles carry pressed state; sortable headers carry sort state
Screen readerPredicted scores carry a label giving both numbers and their meaning, since splitting them across two rows loses that context visually
Colour independence, worked through

A user who cannot distinguish the green tiers still reads "High edge" in the chip, sees the heavier border, and sees the rail on the card's edge. A user who cannot see the orange live dot still reads the word LIVE. Every signal in the system has at least two encodings.

Found in the pre-existing interface, and closed

Three failures were recorded during the audit: a focus outline suppressed with no replacement, leaving the sport selector with no keyboard indication; a reduced-motion preference honoured by exactly one rule; and white heading text on a near-white panel, which is invisible rather than merely low-contrast. All three are fixed, along with every other accessibility defect the audit found — including two contrast failures on interactive labels that were worse than anything the original brief had listed, and a sortable table header that announced itself to a screen reader as a control the keyboard could not operate.

10  Voice and governanceScoreGenius

How the product speaks

Plain, factual, unhedged. The app reports; it does not persuade or apologise.

Write thisNot this
Odds not yet postedOdds unavailable at this time
No NBA games on August 4Sorry, nothing to show!
Roof closedWeather N/A

High edge · DETStrong value pick!

Rules

  • Never imply certainty the model lacks. No "lock", "guaranteed", "sure thing".
  • State facts, not feelings.
  • Sentence case for headings and buttons; uppercase only for monospaced micro-labels.
  • Team names in full in prose; abbreviations only in chips.
  • No exclamation marks. No emoji.
Why this matters here specifically

The product sits next to betting markets. Language that oversells a prediction is both a credibility risk and a regulatory one. Understatement is the safer and the more convincing register.

Governance

SituationWhat to do
Need a colour that is not in the paletteThe palette is missing something. Add it to the system first, in both themes, with a contrast check — never inline in a component.
Need a component that does not existAdd it to the library rather than styling it locally. One is owed already: buttons and inputs, still styled per call site.
Need a size off the type scaleOne of the fourteen roles is probably right. If none is, add a role rather than a one-off value.
A change looks right in one themeIt is not finished. Both themes ship together.
The system's own record

This document summarises a specification maintained in the repository alongside the code, so it travels with the product rather than living in a design tool. That specification also records what the application actually knows — including two facts the code implies but does not deliver, which had already misled a reader once.
